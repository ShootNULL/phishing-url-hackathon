# Фишинговые URL, хакатон АВ Софт

Классификатор фишинговых сайтов по URL и сохраненному HTML страницы. Метка 1 означает фишинг, 0 безопасный сайт, метрика F1.

## Результат

F1 на кросс-валидации (5 фолдов) 0.9909, на публичном лидерборде 0.995079. Итоговый ответ лежит в `submission_v2.csv`.

Как росло качество (F1 на кросс-валидации):

| Что добавлено | F1 |
|---|---|
| tf-idf по символам URL и логистическая регрессия | 0.954 |
| признаки URL, частоты и целевое кодирование по хосту и домену, стек на CatBoost | 0.973 |
| текст и структура HTML страницы | 0.991 |

Нейросеть по символам URL сама по себе слабее (0.948), но в стеке дает разнообразие.

## Идея решения

Двухуровневая схема, все предсказания первого уровня считаются по фолдам (out-of-fold).

Первый уровень:
- логистические регрессии на tf-idf по словам и символам: весь URL (два варианта), хост, путь с параметрами;
- логистические регрессии на тексте страницы (заголовок, видимый текст, action форм, внешние домены в ссылках) и отдельно на заголовке;
- CNN по байтам URL.

Второй уровень, CatBoost. Входы:
- предсказания первого уровня;
- признаки URL (`features.py`): длины, энтропия, IP и punycode, подозрительные слова, бесплатные хостинги, сокращатели ссылок;
- признаки HTML (`extract_content.py`): формы, поля с паролем, внешние action, внешние ссылки и скрипты, бренды в тексте, припаркованные и error-страницы;
- целевое кодирование и частоты по хосту, домену, зоне и заголовку.

Число итераций фиксировано, усреднение по 3 сидам на 5 фолдах. Порог выбирается по OOF под F1 (0.53).

## Структура

```
extract_content.py   разбор HTML из *_with_content.csv, признаки и текст страницы
features.py          разбор URL и признаки по нему
cnn_url.py           CNN по байтам URL
pipeline.py          модели первого уровня, стек, порог, ответ
replay.py            быстрая проверка по сохраненным предсказаниям
run_all.sh           полный запуск
cache/stack_v2.npz   предсказания стека для быстрой проверки
submission_v2.csv    итоговый ответ
requirements.txt     версии библиотек
environment.txt      окружение
```

## Окружение

macOS 26.5.1, Apple M1 Pro (8 ядер, 16 ГБ), Python 3.12.13, GPU не нужен. Подробности в `environment.txt`.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Быстрая проверка

Собирает ответ из сохраненных предсказаний, без обучения. Нужен только `train_6dd2c989.csv`.

```bash
python replay.py
```

Скрипт печатает порог, OOF F1 и сколько строк отличается от `submission_v2.csv`.

## Полное воспроизведение

```bash
./run_all.sh
```

То же по шагам:

```bash
python extract_content.py   # около 20 минут, HTML -> cache/content_*.parquet
python cnn_url.py           # около 15 минут на MPS, cache/cnn_url.npz
python pipeline.py          # около 15 минут, итог в submission_v2.csv
```

Сиды везде 42. Если удалить `cache/`, все посчитается заново.

Я перезапускал все с нуля в чистом окружении по `requirements.txt`: результат отличается от приложенного `submission_v2.csv` в 8 строках из 16000, F1 тот же до четвертого знака. Причина в CNN на Apple MPS: обучение PyTorch на нем не детерминировано. Остальные шаги детерминированы.

## Что честно по методу

- метки теста не используются нигде;
- признаки, которые считаются по меткам (целевое кодирование), и предсказания первого уровня считаются по фолдам;
- порог подбирается по OOF, а не по лидерборду.

## Ограничения

- по одному URL качество около 0.973, остальное дает HTML страницы, поэтому нужен архив организаторов;
- в разметке есть шум: в разборе ошибок около сотни писем с уверенностью модели больше 95% (например, `login.yahoo.com` помечен как фишинг), потолок по F1 ниже 1.0;
- часть страниц в архиве мертвая (index of, domain not available), по ним ничего нельзя сказать.
